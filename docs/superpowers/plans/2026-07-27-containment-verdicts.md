# Containment Verdicts (`allow_contained`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a fifth guard verdict `allow_contained` (between `warn` and `require_approval`) that lets a hook-governed agent execute file-scoped acts inside an isolated git worktree, stages the diff for one-click operator Promote/Discard on /approvals, and lands promoted diffs through a governed, act-hash-bound, single-use merge grant.

**Architecture:** The severity ladder in `app/lib/guard/internal.ts` gains the new rung; a single finalize pass in `evaluateGuard` (after all raises/overrides, before persist/result) enforces server-side eligibility (only provably file-scoped acts) and capability negotiation (callers that don't advertise `allow_contained` get `require_approval` — skew only tightens). The verdict is produced only by `risk_threshold` policies via a new `contain_above` band. Containment state lives as four new columns on `action_records` (migration 0064); staged diffs ride the existing artifacts system; promotion reuses `applyOperatorApprovalGrant` unchanged via a synthetic pre-approved `containment_promote` action row.

**Tech Stack:** Next.js 16 App Router (TS routes), Drizzle/Postgres (Neon), Python hooks (stdlib), Node SDK (`sdk/dashclaw.js`), Python SDK, vitest, existing policy-smoke harness.

## Global Constraints (from RFC + program doc — every task implicitly includes these)

- **Non-negotiable 1:** version skew only tightens — a caller that does not advertise `client_capabilities: ['allow_contained']` NEVER receives `allow_contained`; it receives `require_approval` with breakdown note `_containment: { downgraded_to_interrupt: true }`.
- **Non-negotiable 2:** only provably file-scoped acts are containable, enforced server-side: `act.kind === 'file'`, or `act.kind === 'shell'` classified `apply` with zero flags and no git network subcommand. HTTP, SQL, payments, deploys are NEVER contained regardless of policy.
- **`block` is never downgraded, by anything, ever.** Grants only downgrade `require_approval` → `allow`. New logic may only RAISE (tighten-only charter) — except the negotiation pass, which converts `allow_contained` → `require_approval` (a tighten, severity 2→3).
- No new tables. One new route (`POST /api/actions/[actionId]/containment`). Migration number **0064** (next free after 0063).
- All SQL through `app/lib/repositories/*` (`route-sql:check` gates it). Guard-cache tests need `__resetGuardCaches()`.
- Risk scores 0–100. `guard_decisions.created_at` is TEXT on fresh schemas — `::timestamptz` in SQL touching it.
- UI: tokens only, never hex; read `.impeccable.md` first; orange only on the awaiting-promotion attention cue.
- `DASHCLAW_GUARD_FALLBACK` env enum (`app/lib/env.ts:22`) is deliberately NOT extended — a degraded decision must never be `allow_contained`. `GUARD_ACTIONS` in `validate.js:387` is deliberately NOT extended — policy authors cannot set `rules.action: 'allow_contained'`; only the `contain_above` band produces it.
- MCP server gets NO `allow_contained` support in v1 (it never advertises the capability, so negotiation guarantees it never sees the verdict). Its pre-existing `DashclawDecision` type bug (missing `"warn"`) IS fixed in Task 12.
- Hook copies: canonical `hooks/` is hand-edited; `plugins/dashclaw/hooks/` is regenerated by `npm run bundles:refresh` (pre-commit does this); `.claude/hooks/` is a manual copy — sync the 3 changed scripts explicitly.
- Docs/counts in the same ship: routes 123→124 files, Node SDK 37→39, Python SDK 57→59, CLI +1 subcommand group. `scripts/check-doc-counts.mjs --strict` before commit.

## Design decisions locked against live code (do not re-litigate)

1. **Ladder values:** `{ allow: 0, warn: 1, allow_contained: 2, require_approval: 3, block: 4 }`. `sevOf` unknown→0 behavior unchanged (server is single-deploy; skew is a client concern handled by negotiation).
2. **Finalize pass placement:** in `evaluateGuard` immediately after the two `applyBlockOverride(...)` calls (`evaluate.ts:1119-1120`), before `GuardFinalizeInput` is built — so persistence, simulate previews, and the returned result all see the negotiated decision.
3. **Promotion grant = synthetic action row.** Promote click creates ONE `action_records` row via `createActionRecord`: `action_type: 'containment_promote'`, canonical goal/act (below), `status: 'running'`, `approved_by: <operator userId>`, `approved_at: now` — exactly the post-approval shape `applyOperatorApprovalGrant` matches (org+agent+goal+act-hash, 15-min TTL, single-use atomic consume). The CLI's guard call for the merge consumes it. No grant machinery is added or modified.
4. **Canonical promotion act** (must be byte-identical server-side and CLI-side):
   - `declared_goal`: `containment promote <contained_action_id>`
   - `act`: `{ kind: 'shell', command: 'git merge --no-ff <containment_ref>' }` where `containment_ref` is the branch name stored on the contained action (e.g. `dashclaw/contained-abc123`).
5. **Builtin raise:** `action_type === 'containment_promote'` always raises to `require_approval` (`builtin:containment_promote`) inside `runEvaluation` before the grant passes — ungoverned merges always interrupt; the promote-click grant downgrades exactly one.
6. **Bash containment via instructive deny only.** The Bash tool input schema has no `cwd` field; rewriting command text is fragile. `updatedInput` rewrite applies to Edit/Write/MultiEdit file paths only (if the Task 1 spike passes); eligible Bash always gets the instructive-deny redirect. (Deviation from RFC's "rewrite cwd" — RFC's own fallback strategy, applied per-tool.)
7. **Status flow:** guard `?record=true` on `allow_contained` creates the action with `containment_status='contained'`. Posttool PATCHes `containment_ref` + uploads the diff artifact. Stop hook flips `contained`→`awaiting_promotion` (agent-side transition, allowed via PATCH). Operator route flips `awaiting_promotion`→`promoted`|`discarded` (admin-only). WHERE-gate legality checks, `recordApproval` pattern.
8. **No demo-route entry** for the new surfaces (Preflight precedent: additive sections render empty in demo; the approvals page fetch wraps in try/catch). frontend-verify runs against seeded local data, not demo mode.
9. **Approvals UI is a section, not a tab** — the page is a vertical stack of sections (`PlanReviewCard`s, `LivePlansSection`, pending actions); a Containment section follows `LivePlansSection`'s pattern. (RFC's "tab" wording is incidental; program doc: RFC invariants win over incidental details.)
10. **`contain_above` validity:** integer 0–100, requires `rules.action === 'require_approval'` in the same policy, and `contain_above < threshold` strictly. Band: `contain_above <= score < threshold` → `allow_contained` (eligibility-checked); `score >= threshold` → `require_approval` as today. Ineligible act in band → `require_approval` (deliberate tightening; RFC §Verdict sources).

/**
 * Containment Verdicts (allow_contained) — server-side eligibility, capability
 * negotiation, and the canonical promotion act. RFC 2026-07-06-containment-verdicts.
 *
 * Invariants enforced here:
 *  - only provably file-scoped acts are containable (eligibility);
 *  - a caller that does not advertise support NEVER sees allow_contained
 *    (negotiation converts to require_approval — version skew only tightens).
 */
import { classifyAct } from './evidence';
import type { GuardEvalContext } from './types';
import type { GuardAccumulator } from './evaluate';

const CAPABILITY = 'allow_contained';
// git subcommands that touch the network — file-scoped proof fails even though
// the shell classifier grades them 'apply'.
const GIT_NETWORK_RE = /\bgit\s+(push|pull|fetch)\b/i;

export function isContainableAct(context: GuardEvalContext): { eligible: boolean; basis: string } {
  const act = context.act as { kind?: string; command?: string } | undefined;
  if (!act || typeof act !== 'object') return { eligible: false, basis: 'no act attached' };
  if (act.kind === 'file') return { eligible: true, basis: 'file' };
  if (act.kind !== 'shell') return { eligible: false, basis: `act kind ${String(act.kind)} is never containable` };
  const cls = classifyAct(context.act);
  if (!cls) return { eligible: false, basis: 'unclassifiable shell act' };
  if (cls.derived_action_type !== 'apply' || cls.flags.length > 0) {
    return { eligible: false, basis: `shell class ${cls.derived_action_type}${cls.flags.length ? ` [${cls.flags.join(',')}]` : ''} not provably file-scoped` };
  }
  if (typeof act.command === 'string' && GIT_NETWORK_RE.test(act.command)) {
    return { eligible: false, basis: 'git network subcommand' };
  }
  return { eligible: true, basis: 'shell_file_ops' };
}

export function clientAdvertisesContainment(context: GuardEvalContext): boolean {
  const caps = context.client_capabilities;
  return Array.isArray(caps) && caps.includes(CAPABILITY);
}

export function finalizeContainment(
  context: GuardEvalContext,
  acc: GuardAccumulator,
  riskBreakdown: Record<string, unknown>,
): { containment?: { status: 'contained'; basis: string } } {
  if (acc.highestDecision !== CAPABILITY) return {};
  const eligibility = isContainableAct(context);
  if (!eligibility.eligible) {
    acc.highestDecision = 'require_approval';
    acc.reasons.push(`Containment ineligible (${eligibility.basis}) — interrupting instead`);
    riskBreakdown._containment = { downgraded_to_interrupt: true, reason: eligibility.basis };
    return {};
  }
  if (!clientAdvertisesContainment(context)) {
    acc.highestDecision = 'require_approval';
    acc.warnings.push('Verdict was allow_contained but the caller does not advertise containment support — emitted require_approval (skew only tightens)');
    riskBreakdown._containment = { downgraded_to_interrupt: true, reason: 'client capability not advertised' };
    return {};
  }
  return { containment: { status: 'contained', basis: eligibility.basis } };
}

export function buildPromotionGoal(containedActionId: string): string {
  return `containment promote ${containedActionId}`;
}

export function buildPromotionAct(containmentRef: string): { kind: 'shell'; command: string } {
  return { kind: 'shell', command: `git merge --no-ff ${containmentRef}` };
}
